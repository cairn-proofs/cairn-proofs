# The content digest is a pure, reproducible function of the bundle's content
# bytes: the content-descriptive Config_Blob (projectId ONLY) plus the content
# layers, with `org.opencontainers.image.created` pinned to epoch 0 (no
# wall-clock / randomness folded in). A fixed fixture therefore yields a fixed
# digest. Artifact-kind is NOT in the content manifest: the Config_Blob carries

# signed Producer_Attestation_Referrer (`artifactKind` claim), so it is NOT in the content
# digest. projectId remains in BOTH the Config_Blob and the manifest annotations,
# so projectId IS in the content digest. The producer CLAIM fields
# (artifactKind, controls, catalogOrProfileUuid, assessmentPeriod, assessor,
# assessmentId, supersedes, orgId, tenantId) are NOT — they live only in the
# Producer_Attestation_Referrer.
